# Render Backend Deployment Guide
## Load Shedding & Power Outage Management System

This guide provides step-by-step instructions for deploying the Express + TypeScript backend (`apps/api`) on [Render](https://render.com).

---

## 1. Quick Overview & Architecture

* **Live Production URL:** `https://load-shading-balance.onrender.com`
* **Service Status:** Active & `HEALTHY` (Database: `UP`, Redis: `UP`)
* **Service Type:** Web Service (Node.js 20 LTS)
* **Root Directory:** `.` (Repository root, to leverage npm workspaces)
* **Build Command:** `npm install && npm run build:backend`
* **Start Command:** `npm run start:backend`
* **Health Check Path:** `/api/v1/health/live` (or `/api/health`)
* **Default Port:** `10000` (automatically provided by Render via `$PORT`)

## 2. Complete Environment Variables Dictionary

Configure these environment variables in your Render Web Service dashboard under the **Environment** tab:

### 2.1 Required Variables

| Variable Name | Description | Example Value | Notes |
|---|---|---|---|
| `NODE_ENV` | Environment mode | `production` | Enforces production optimizations, hides error stack traces, and activates security headers. |
| `PORT` | Listening port | `10000` | Automatically injected by Render; backend binds to `0.0.0.0:$PORT`. |
| `OPERATIONAL_TIME_ZONE` | National power grid timezone | `Asia/Dhaka` | Critical for correct same-day schedule rotation and calendar cut calculations. |
| `AUTH_SECRET` | Secret key for JWT & Auth session tokens | `a-secure-random-string-at-least-32-chars-long` | Auto-generated by Render Blueprint, or generate with `openssl rand -hex 32`. |
| `FRONTEND_URL` | Allowed frontend origins for CORS and Socket.io | `https://load-shading-balance.vercel.app` | Comma-separated list supported (e.g. `https://load-shading-balance.vercel.app,http://localhost:3000`). Trailing slashes are automatically sanitized. |
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://user:password@ep-xyz.neon.tech/loadshedding?sslmode=require` | Connection URL from Neon, Supabase, or Render Managed PostgreSQL. |

### 2.2 Optional Variables (Integrations & Fallbacks)

| Variable Name | Description | Default / Fallback | Notes |
|---|---|---|---|
| `REDIS_URL` | Upstash or Render Redis connection URL | *(empty / in-memory fallback)* | When omitted, the API gracefully falls back to in-memory caching and locks. Format: `rediss://default:password@xyz.upstash.io:6379`. |
| `TWILIO_ACCOUNT_SID` | Twilio Account SID for SMS alerts | *(empty / console simulation)* | If omitted, SMS dispatches are simulated and safely logged to console. |
| `TWILIO_AUTH_TOKEN` | Twilio Auth Token | *(empty)* | Required if sending real SMS via Twilio. |
| `TWILIO_PHONE_NUMBER` | Twilio sender phone number | `+1234567890` | E.164 formatted sender phone number. |
| `ENABLE_DEMO_SIMULATION`| Background grid load fluctuations | `false` | Set to `true` only if you want automatic test load changes in demo mode. |
| `UPLOAD_DIR` | Local storage directory for repair photos | `./uploads` | Ephemeral on Render free tier. For persistent production, attach a Render Disk or S3 bucket. |

## 3. Deployment Methods

### Option A: Automatic Blueprint Deployment (Recommended)

The repository includes a root `render.yaml` blueprint.

1. Push your latest code to your GitHub repository.
2. In the [Render Dashboard](https://dashboard.render.com), click **New +** &rarr; **Blueprint**.
3. Select your repository (`load_shading_balance`).
4. Render will detect `render.yaml` and configure the Web Service automatically.
5. In the configuration prompt, provide your:
   - `DATABASE_URL`
   - `FRONTEND_URL`
   - `REDIS_URL` (optional)
6. Click **Apply**. Render will build and deploy the backend automatically.

---

### Option B: Manual Web Service Setup via Render Dashboard

If configuring manually without the blueprint:

1. In Render Dashboard, click **New +** &rarr; **Web Service**.
2. Connect your GitHub repository.
3. Configure the following fields:
   * **Name:** `load-shedding-backend` (or your preferred name)
   * **Region:** Choose the region closest to your users or database (e.g., `Oregon`, `Frankfurt`, `Singapore`).
   * **Branch:** `main`
   * **Root Directory:** Leave blank (defaults to repository root `.`)
   * **Runtime:** `Node`
   * **Build Command:**
     ```bash
     npm install && npm run build:backend
     ```
   * **Start Command:**
     ```bash
     npm run start:backend
     ```
   * **Instance Type:** `Free` (or `Starter`)
4. Expand **Advanced**:
   * **Health Check Path:** `/api/v1/health/live`
   * **Auto-Deploy:** `Yes`
5. Click **Add Environment Variable** and enter the variables from Section 2.
6. Click **Create Web Service**.

## 4. Database Setup & Initial Seeding on Render

Once your database is connected via `DATABASE_URL`:

### Step 1: Push Database Schema
To synchronize the Prisma schema with your PostgreSQL database:

* **From your local machine:**
  ```powershell
  $env:DATABASE_URL="your-production-database-url"
  npm run db:push
  ```
* **Or via Render Shell (Dashboard &rarr; Service &rarr; Shell):**
  ```bash
  npm run db:push
  ```

### Step 2: Seed Initial Grid Topology & Test Accounts (Optional)
To populate initial zones (Dhanmondi, Mirpur), substations, hospital critical feeders, and all 5 user roles:

* **From your local machine:**
  ```powershell
  $env:DATABASE_URL="your-production-database-url"
  npm run db:seed
  ```
* **Or via Render Shell:**
  ```bash
  npm run db:seed
  ```

## 6. Important Operational Notes for Render Free Tier

1. **Cold Starts (Spin-Down on Inactivity):**
   Render's free tier spins down web services after 15 minutes of inactivity. When a new request arrives, it may take 30–50 seconds to boot up. For university project demonstrations or continuous operation, pinging `/api/v1/health/live` periodically or upgrading to the Starter plan avoids spin-down.
2. **Ephemeral File Storage:**
   Technician repair photos uploaded to `/uploads` are stored on the local container filesystem. On the free tier, files reset when the service restarts. For permanent photo storage across redeploys, attach a Render Persistent Disk (mounted to `/var/data/uploads` and set `UPLOAD_DIR=/var/data/uploads`) or integrate AWS S3.
3. **WebSockets (Socket.io):**
   Render natively supports persistent WebSockets and Socket.io connections on both free and paid plans. Ensure `FRONTEND_URL` matches your client domain so handshake CORS succeeds.
